# Modelo — Checklist de release

**REL-___ · Commit/versão:** ___  
**Ambiente:** homologação / piloto / produção  
**Aprovador funcional e autoridade operacional:** ___

- [ ] Escopo, alterações e dependências identificados.
- [ ] DoD, testes, UAT e riscos residuais documentados.
- [ ] Requisitos de segurança/privacidade/acessibilidade aplicáveis revisados.
- [ ] Segredos e privilégios mínimos conferidos; HTTPS e configurações corretos.
- [ ] Migrações, backup e recuperação/rollback tratados com realismo.
- [ ] Logs saneados, métricas, alertas e responsáveis preparados.
- [ ] Autorização do destino identificada.
- [ ] Deploy e smoke tests feitos; incidentes registrados.
- [ ] Decisão de manter, corrigir, desativar ou reverter registrada.

**Data, executor, evidência e comunicado:** ___

Reversão de código não desfaz automaticamente dados ou migrações.
